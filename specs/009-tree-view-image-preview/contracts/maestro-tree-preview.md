# Contract: Maestro flows for feature 009

The workspace flows go in `validation/maestro/tree/`. The flows that need a host step between their parts
go in `validation/maestro/staged/` and are listed in `staged/pairs.txt`. All of them run on API 31 and
API 36 against the live FTP, SFTP and WebDAV containers (`pnpm e2e:android`, D012). Each workspace flow
is self-contained and starts with `clearState: true`; in a staged line, only the first part does.

Host scripts run only between the parts of a staged line (`run_hook` in
`scripts/validation/android-flow.sh`), never inside a workspace flow. The runner gives hooks
`SYNCSCOPE_STATE_ROOT` (the SFTP service's fixture tree) and `ANDROID_SERIAL`. Staged flows therefore use
the SFTP seam, as every existing staged line does.

## Fixtures

- **Device**: `device-fixtures.sh` gains a `tree` set, written under `scan/tree/`:
  - `Album/2024/` with 5 JPEGs, `a1.jpg`–`a5.jpg`;
  - `Album/2025/` with `b1.jpg`, `new.jpg` and `clip.mp4` (2 s, H.264, generated by
    `fixture-images.sh` with `ffmpeg` while the fixtures are being generated, then checked in like the
    images);
  - `Album/Docs/` with `doc.pdf`;
  - `Empty/`;
  - `Loose.jpg`.

  The set uses `immutable_set`. `device-fixtures.sh` runs once per API level, before the workspace
  flows, and the staged lines run after the workspace in the same API run. So within one API run, the
  staged lines see what the workspace flows left: `tree/05` deletes `a1`–`a3` only, and `staged/10` uses
  `a4` and `a5`. A changed set is reseeded before the next API level's workspace flows.
- **Server**: the same tree, **including** `Album/2025/new.jpg`, under `<root>/scan/tree/` on all three
  servers, and in the before-manifest the services compare when they stop. The resync line removes
  `new.jpg` from the SFTP tree and then restores it, using `remove-recheck-file.sh` and
  `restore-recheck-file.sh` with the path as an argument. The runner's cleanup also restores it, so an
  interrupted run leaves the seeded tree.

## Flows

| Flow | Protocol | Steps (summary) |
| --- | --- | --- |
| `tree/01-expand-collapse-sftp` | SFTP | Scan the `tree` set. View drop-down → Tree. Expand `Album` → `2024`, `2025`, `Docs` appear indented. Expand `2025` → 3 files. Collapse `Album` → children gone. Switch to List and open `Album` → the same three folders (US1 sc. 1). |
| `tree/02-filter-dimmed-ftp` | FTP | Filter "Unsynced" → `Album/Docs` is dimmed, shows "0" and still expands (US1 sc. 3, SC-002). |
| `tree/03-preview-image-webdav` | WebDAV | Tap `Loose.jpg` in the gallery, in list view and in tree view → the preview opens each time with the image (`preview-image` visible). Back returns to the same view and position (US1 sc. 2). |
| `tree/04-video-gallery-preview-sftp` | SFTP | The gallery shows the MP4 tile with a play badge and "0:02". List and tree rows of the MP4 show a thumbnail with a play badge. Tap → `preview-video` plays, muted, and the controller's pause and seek respond (US1 sc. 4–6, SC-004). |
| `tree/05-tree-select-delete-ftp` | FTP | In tree view, expand `Album/2024`, long-press `a1.jpg` (SYNCED), tap `a2.jpg` → the bar shows "2 selected". Open the preview of `a3.jpg` and use "Select this file" → "3 selected". Delete → the existing confirmation → the files are gone from the tree (selection parity). `a4.jpg`, `a5.jpg`, `Album/2025` and `Loose.jpg` stay for the staged lines. |
| `staged/09-resync-a` / `-b` / `-c` | SFTP | **a**: set up the SFTP repository and the `tree` source, no scan. Hook: `remove-recheck-file.sh scan/tree/Album/2025/new.jpg`. **b**: `Album/2025` holds `b1.jpg`, `new.jpg` and `clip.mp4`; full scan → `new.jpg` shows "Not backed up". Hook: `restore-recheck-file.sh scan/tree/Album/2025/new.jpg`. **c**: relaunch (automatic refresh) → `new.jpg` shows "Backed up" with no full scan, and the summary card shows "Re-checked 1 server folder, 1 file now backed up" (FR-003, SC-003). |
| `staged/10-selection-survives-a` / `-b` | SFTP | **a**: scan the `tree` set, select `a4.jpg` and `a5.jpg`. Hook: `change-device-files.sh scan/tree/Album/2024/a4.jpg` touches `a4.jpg`. **b**: return to the foreground → the refresh completes → "1 selected" and the notice "1 selected file changed or was removed, so it was unselected." |
| `staged/11-toolbar-halves-a` / `-b` | SFTP | **a**: scan the `tree` set (Files shows no toolbar until a snapshot exists) and open Files, so the sort and view drop-downs are on screen. Hook: `assert-equal-halves.sh` → the buttons `files-sort` and `files-view` are each 50 % ± 2 % of `files-toolbar`, read from a `uiautomator dump` (the hook fails the line otherwise). It measures the buttons, not their `-control` wrappers, which already have `flex: 1` and measure half the row even while the bug is present. **b**: both drop-downs are still visible and open (US1 sc. 7, FR-006). |

The edge cases "removed since the scan" and "unplayable video" are covered by Jest and Robolectric tests,
not Maestro. Making a file unreadable between the scan and the tap is not reproducible on the emulator
without a hook racing the UI. This is recorded as a deviation under the plan's Complexity Tracking.
