# Brief
Lets plan implementing a new android application.
I want to create a cloud sync checking app.

# Purpose
This application should allow me to check which of selected (groups/directories) of files on my device are synced with my cloud.

# Solution

An application should be created that:
* Will take a:
** Cloud repository url - FTP, sFTP, WebDAV should be supported
** User credentials
** Selection of local device directories to check.
* Display a gallery of files from selected directories.
* Mark synced files.
* Allow to filter only synced, unsynced files
* Allow to multiselect files from gallery
* Delete selected file
* Preview a file (image only)
* Have a tree view and list view additional to gallery view

# How

Use React-Native framework.

Create a slick and modern, user friendly design.

# Constitution

* Tests are mandatory both unit and e2e.
* Created code should follow most important development rules: KISS, YAGNI, DRY, consistency, decoupling.
* Always add and keep in sync documentation for the project at `./docs`
* Keep README.md up to date with user focused instructions at first.

# Q&A

How should a local file be considered synced with its remote counterpart?
Path + size + modified time
What should “Delete selected file” delete?
Local files only
How should local folders map to cloud locations?
One remote root for all folders
What should happen if an existing Android app adequately meets the brief?
Build only if major gaps remain

With multiple selected folders under one remote root, how should collisions such as two folders named “Pictures” be prevented?
It doesn't matter. It is important that given file is backed up. That means there can be duplicates on both device and remote (same file in multiple directories. Directory tries might not match between device and remote. Android often have app dependent structure of directories (e.g. picture albums), cloud syncing often flattens it, and have its own solution for directories / albums. If needed find solution on how to distinguish directories for the user knowledge only (where given folder is coming from). Or an autogenerated alias.
Protocols expose modified times at different precision. How should timestamps match?
Compare at shared protocol precision
Should scans keep running while the app is backgrounded?
Foreground app only, but show progress.
Which local folder sources should the first release permit?
On-device and removable storage only

When local and remote directory trees differ, what proves that a local file exists remotely?
File name + size + modified time
Which selected files may be deleted locally?
Synced by default, allow unsynced with stronger warning
What authentication scope should version one support?
Username and password only
How will the first release be distributed?
Local debug/release APK
